クイックスタート

空のソフトから最初のモデルを出すまで、最短ルートはこの 6 ステップです。各ステップの詳細は後続の各章で説明します。

  1. プロジェクトを追加 —— 左側の「+ プロジェクトを追加」をクリックし、名前を入力します。
  2. データセットを追加 —— プロジェクトノードを右クリック →「データセットを追加」。
  3. データをインポート —— データセットを選び、上部の「インポート」をクリックして、画像フォルダとアノテーションフォルダをそれぞれ選びます。
  4. データを確認 —— 「データセットのプロパティ」をクリックし、クラスと数が間違っていないか確認します。
  5. 学習 —— 「学習」をクリックし、タスク種別とデータセットを選び、残りは既定のままにして「学習を開始」をクリックします。
  6. 結果を見る —— 学習が終わったら「モデル」でこの記録を探し、「テスト」をクリックして検証セットで 1 回実行します。納品するなら PDF レポートを書き出します。
手元にまだアノテーション済みのデータがない場合は、まず第 3 章「アノテーション」を参照してください。

1. 画面とプロジェクト

1.1 メイン画面のレイアウト

メイン画面は 3 つのブロックに分かれます。左側がプロジェクトの管理、中央が画像の表示、ツールバーは上部です。

  • 左側のプロジェクトツリー —— プロジェクトとデータセットが階層で並びます。データセットの後ろにはアノテーションの進捗(例: 126/128)が表示されます。名前の前の丸印はメモリに読み込まれているかどうかを示し、緑は読み込み済み、赤は未読み込みです。
  • 中央の画像エリア —— サムネイルをページ単位で閲覧します。下部中央にページ送りのコントロールがあり、2 つの矢印がページ番号を挟み、現在のページ番号がハイライトされます。ページ番号にマウスを乗せると、現在の絞り込みで全部で何枚あるかを確認できます。
  • 上部ツールバー —— 表示倍率、アノテーション絞り込みのドロップダウン、および編集・削除・インポート・エクスポート・データセットのプロパティ・学習・モデル・ログなどのボタンがあります。

1.2 プロジェクトとデータセット

プロジェクトを追加: 左側の「+ プロジェクトを追加」をクリックし、名前を入力して OK を押します。プロジェクトはデータセットの入れ物で、各データセットは必ずいずれかのプロジェクトに属します。

プロジェクトノードを右クリック:

  • データセットを追加 —— プロジェクトの下に新しいデータセットを作成します
  • プロジェクトをエクスポート —— プロジェクト全体のデータセットとアノテーションを指定の形式で書き出します
  • 名前を変更 —— プロジェクトの名前を変更します
  • プロジェクトを削除 —— 配下のデータセット・アノテーション・学習記録もまとめて消去します

データセットノードの右クリックは 1 つのデータセットに対する操作です: インポート / エクスポート / 移動 / 名前を変更 / 削除。

データセットをダブルクリックすると読み込まれます。画像とアノテーションを再スキャンし、キャッシュを再構築したあと、右側で閲覧できるようになります。すでに読み込み済みのもの(行内に状態の丸印がある)は、もう一度ダブルクリックしても再スキャンは行いません。

1.3 データのインポート

データセットを選び、上部の「インポート」をクリックすると、インポートダイアログが開きます:

  • 画像パス —— 画像があるフォルダ
  • ラベルパス —— アノテーションファイルがあるフォルダ
  • ラベル形式 —— Yolo txt / Labelme json / サブフォルダで分類としてインポート
分類データセットでは「サブフォルダで分類としてインポート」を選びます。各サブフォルダ名がそのまま 1 つのクラスになり、アノテーションファイルは不要です。
OCR は Labelme json を使います。テキストボックスのラベルは「text」に固定され、インポート後は自動的にテキスト検出データセットとしてマークされます。

1.4 データセットのプロパティ

データセットを選び、上部の「データセットのプロパティ」をクリックすると、画像パス、ラベルパス、そしてラベル分布の棒グラフ(各クラスにアノテーションボックスがいくつあるか)が表示されます。どのクラスのサンプルが少ないか、一目で分かります。

1.5 表示言語

ツールバーの一番右は表示言語のドロップダウンで、9 言語から選べます: 中文、English、繁體中文、日本語、한국어、Deutsch、Español、Français、Tiếng Việt。

選ぶとメイン画面がすぐに切り替わり、すでに開いているログや学習キューのウィンドウも一緒に更新されます。まだ開いていないダイアログは、次に開いたときに新しい言語になります。選択は記憶され、次回起動時も同じ言語のままです。ドロップダウンの各項目はその言語自身の表記で並んでいるので、現在の画面がどの言語であっても、選ぶべき項目が分かります。

2. アノテーション

2.1 アノテーション画面を開く

データセットを選んだあと、サムネイルを右クリックして「アノテーション」を選ぶか、サムネイルを直接ダブルクリックします。

2.2 枠を描く

アノテーション画面の上部ツールバーには 3 通りの描き方があります:

  • 矩形 —— マウスをドラッグして枠を描きます
  • ポリゴン —— 頂点を順にクリックし、ダブルクリックまたは Enter で確定します(セグメンテーションのタスク用)
  • テキスト —— 先に上部の「テキストアノテーション」スイッチをオンにしてから枠をドラッグし、離すと入力欄が開くので文字を入力します。ダブルクリックで変更できます(OCR のタスク用)

テキストボックスは必ず矩形で描きます。傾いた文字も水平な枠で覆えば問題ありません —— 学習時にはポリゴンも水平な外接矩形として扱われるため、輪郭をなぞって描いても効果はありません。

ツールバーには「画像を削除」もあり、現在の 1 枚を削除できます。

クラスは右側のラベル一覧から選びます。

「アノテーションを表示」スイッチですべての輪郭(枠線・ラベル・頂点ハンドル)をいつでも非表示にでき、元画像を確認しやすくなります。すでに貼り付け済みで、まだ確定していない内容は輪郭だけが隠れ、模様はそのまま表示されるので、これをオフにすると「貼り終えたときの見え方」をちょうどプレビューできます。

右下の「アノテーション情報」には、この画像の各アノテーションオブジェクトの形状(矩形 / ポリゴン)、頂点数、面積が一覧表示されます。そのすぐ下の画像情報には、現在の画像の幅 × 高さ × チャンネル数(例: 505×505×3)と通し番号が表示されます。

さらに下がクリップボードです。ポリゴンを右クリックでコピーすると、コピーした領域のサムネイル(120 × 90)が追加されます。最大 9 枚まで保存でき、縦に並んでスクロールできます。最新の 1 枚が既定で選択され、青い枠が付きます。サムネイルを右クリックすると、この 1 枚を削除するか、すべてクリアできます。

2.3 ラベル管理

アノテーション画面の右側はラベル一覧で、上部に「ラベルを追加」があります:

  • ラベル名 —— 複数のラベルはカンマ区切りで、一度にいくつでも追加できます
  • インポート —— 他のデータセットからラベルをまとめて取り込みます
  • 色を選択 —— あらかじめ用意されたパレットから選ぶか、「カスタム色」をクリックして自分で選びます

2.4 クラスを変更する

1 つだけ変更: アノテーションボックスをクリックするとクラスのドロップダウンメニューが開くので、新しいクラスを選ぶだけです。右側のラベル一覧のラベルも、名前の変更・色の変更・削除ができます。

一括で変更: サムネイルを右クリック →「クラスを一括変更」で、変更前と変更後のクラスを入力すると、データセット内のそのクラスのアノテーションがすべて改名されます。

2.5 アノテーションオブジェクトのコピーと貼り付け

ポリゴンのアノテーションを右クリックすると、2 つの操作があります:

  • コピー —— この領域のピクセルをテンプレートとして保存し、同時に右下のクリップボードへサムネイルを生成します
  • 塗りつぶし —— 領域内のピクセルを「塗りつぶし値」の 3 つの入力欄に対応する RGB 色に置き換えます(各チャンネル 0 ~ 255、既定 255)。欠陥を背景色で塗り消すのによく使います

クリップボード内のサムネイルを左クリックで選択し、マウスをキャンバスに移動すると、ポリゴンの点線が付いてきます —— 形は回転後の実際の輪郭で、今回抽選された角度がすでに適用されています。位置と向きをよく確認し、Esc を押して点線を消して通常のマウスモードに戻り、右クリックで「貼り付け」を選んで確定します。

画像の空白部分で右クリックして「貼り付け」を選ぶと、クリップボードで現在選択している 1 枚がマウス位置に貼り付きます。同じ画像でも別の画像でもかまいません。貼り付ける前にツールバーで次の項目を設定しておきます:

  • 角度範囲 —— 貼り付け時にランダム回転する角度の範囲(既定 -180 ~ 180)。点線プレビューにはこの範囲から抽選された角度が使われるので、見たままになります
  • 合成強度 —— 0 ~ 1、既定 0.70。貼り付け時に明るさ補正とエッジのぼかしを自動で行い、貼った部分と背景を自然になじませます。0 にするとそのままハードに貼り付きます
  • 塗りつぶし値 —— R / G / B の 3 つの入力欄(各チャンネル 0 ~ 255、既定 255)。右クリックの「塗りつぶし」と組み合わせて、領域をこの色で塗り消します
  • Ctrl + Z —— 直近の貼り付けまたは塗りつぶしを元に戻します。ピクセルが復元され、それに伴って追加されたアノテーションも一緒に取り除かれます。続けて何度でも戻せます

2.6 ポリゴン領域の明るさ調整

ポリゴンを 1 つ選択し、ツールバーの「設定」で明るさ調整をオンにすると、このポリゴン枠内のピクセルの明暗を変更できます。スライダーをドラッグするか数値を直接入力すると、画像上でリアルタイムにプレビューされます。

  • 範囲 —— 0 ~ 1、既定 0.50 がそのままの状態です。1 に近づくほど明るく(1.00 で約 2 倍の明るさ)、0 に近づくほど暗くなります(0 で真っ黒)
  • 選択中のポリゴンにのみ有効です。矩形の場合、または何も選択していないときはヒントが出るだけで、ピクセルは変化しません。別のポリゴンをクリックするとスライダーはそのポリゴン自身の値に戻り(調整していなければすべて 0.50)、前のポリゴンの明るさを持ち越すことはありません
  • いつディスクに書き込まれるか —— ドラッグ中はメモリ上の変更とリアルタイムプレビューだけです。A / D で画像を切り替えるか、Ctrl + S を押したときに初めて画像ファイルへ書き込まれます
  • 元に戻す —— 1 回の調整は 1 ステップとして記録され、Ctrl + Z で調整前に戻ります。同じ調整の中で何度ドラッグしても 1 ステップとみなされます

2.7 クラスで画像を絞り込む

上部ツールバーのクラスのドロップダウンでどれか 1 つのクラスを選ぶと、画像エリアにはそのクラスを含む画像だけが表示されます。あるクラスを集中的に確認したり、追加でアノテーションを付けたりするときに便利です。

3. 学習

3.1 学習パラメータを設定する

ホーム画面またはモデル画面の「学習」をクリックすると、パラメータ設定が開きます:

  • タスク種別 —— 物体検出 / セグメンテーション / 分類 / 異常検出 / OCR で、データセットの形式に応じて自動的に切り替わります
  • 学習セット / 検証セット —— 複数選択でき、プロジェクトをまたいで組み合わせることもできます
  • デバイス —— 使用可能な GPU が自動で一覧表示されます
  • エポック / オプティマイザ / 早期終了 —— オプティマイザは物体検出とセグメンテーションが adamw、分類が sgd です。早期終了は N エポック連続で改善がなければ打ち切る設定で、0 を入れるとオフになります
  • 学習率 —— 学習の進行中に自動で減衰します
  • バッチ / 画像サイズ / 勾配累積 / スレッド数 —— 画像サイズは 32 の倍数である必要があります。VRAM が足りなければバッチを小さくし、勾配累積を大きくします。効果はバッチを大きくするのと同じです
  • 出力パス —— 空欄にすると時刻に基づいて自動でフォルダが生成されます。「参照」をクリックして指定することもできます

3.2 学習キュー

パラメータを設定したら、「学習を開始」のほかに「キューに追加」をクリックしてタスクをいったん保留し、続けて次の設定ができます。ホーム画面で「学習キュー」をクリックするとキューのウィンドウが開きます:

  • キューは順番に実行され、物体検出 / セグメンテーション / 分類 / 異常検出 / OCR を混在させることができ、1 つ終わると自動で次に移ります
  • 上へ / 下へ / 削除 —— 実行順を調整したり、タスクを削除したりします
  • 編集 —— 選択したタスクのパラメータを変更します
  • 終了済みをクリア —— すでに完了した記録を外に出します
  • キューを開始 —— キューのタスクを先頭から順に実行します
キューは夜間に放置しておくのに向いています。複数のデータセットのタスクを一度に設定しておけば、ソフトが自動ですべて実行し、それぞれモデルを保存します。

3.3 学習の進捗

「学習を開始」をクリックするとホーム画面に戻り、上部に進捗バーとコントロールバーが表示されます:

  • タスク名 + 進捗 —— coco128 学習中 5/100 のような形式で、進捗バーの中に現在のエポックの loss が表示されます
  • 学習を停止 —— いつでも中止でき、すでに完了した部分は保存されます
  • 残り時間 —— 消費した時間から外挿して見積もります
  • VRAM —— GPU の VRAM 使用率で、リアルタイムに更新されます

3.4 学習曲線

モデル管理で学習記録を 1 つ選び、右側の詳細パネルの「すべての指標を表示」をクリックすると、学習曲線のウィンドウが開きます:

  • 上半分は val loss の曲線です
  • 下半分は mAP@50-95 / mAP@50 / AR / F1 / precision / recall などの複数の曲線で、セグメンテーションのタスクでは mask mAP がもう 1 本増えます
  • 右上の「ラベル絞り込み」ドロップダウンで、すべての指標を見るか、特定クラスの曲線に切り替えられます

4. モデル管理

ホーム画面で「モデル」をクリックするとモデル管理が開きます。左側が学習記録の一覧、右側が詳細パネルです。

4.1 一覧と絞り込み

  • 検索ボックス —— プロジェクト / データセット / ラベルのキーワードで絞り込みます
  • タスク / 状態のドロップダウン —— タスクは物体検出 / セグメンテーション / 分類 / 異常検出 / テキスト検出 / テキスト認識から選べます。状態は学習中 / 完了 / 失敗 / 停止済みから選べます
  • データセットごとの最良のみ表示 —— 同じデータセットでは精度が最も高い 1 件だけを残します
  • 一覧の列: タスク、データセット・ラベル、精度、学習日時、所要時間、画像サイズ、操作
  • 精度の列にはカラーバーが付きます —— 緑は 0.8 以上、黄は 0.5 ~ 0.8、赤は < 0.5 です。失敗または停止済みの記録では、この列に状態のテキストが表示され、マウスを乗せると失敗理由を確認できます
  • 行内に 3 つのボタンがあります: テスト(モデルテストを開く)、エクスポート、削除(対応する学習記録も一緒に消去します)

4.2 詳細パネル

任意の行をクリックすると、右側にこの記録の完全なパラメータが表示されます: タスク・規模、状態、精度、学習セット / 検証セット、画像サイズ、エポック数 / 早期終了、バッチサイズ、学習率、オプティマイザ、デバイス、ラベル、学習日時、所要時間、モデルパス。上部には精度曲線のサムネイルもあります。

パネルの下部に 4 つのボタンがあります:

  • すべての指標を表示 —— 学習曲線のウィンドウを開きます(「学習曲線」の節を参照)
  • このモデルをテスト —— このモデルでテストダイアログを開きます(「テストパラメータ」の節を参照)
  • この設定で再学習 —— この記録の学習パラメータをすべて引き継ぎ、もう一度学習を開始します
  • モデルフォルダを開く —— エクスプローラーで重みファイルの場所を開きます

4.3 ONNX のエクスポート

「エクスポート」をクリックしてフォルダを選ぶと、「项目_时间戳」というフォルダが生成されます:

  • モデル .onnx —— 物体検出とセグメンテーションは RF-DETR がエクスポートし、分類と OCR は torch がエクスポートします。名前は「项目_任务_图像尺寸_模型规模.onnx」です
  • classes.txt —— クラス id と名前の対応表です。OCR の認識段は vocab.txt で、1 行 1 文字がそのまま語彙表になります
  • 評価レポート PDF —— 検証セットで自動的に評価を 1 回実行し、テストレポートのテンプレートを再利用します。名前は「…_评估报告.pdf」です
  • examples/ —— C++ / C# / Python から ONNX を呼び出して物体検出・セグメンテーション・分類を行うサンプルコードです。OCR は現在 Python 版のみです

エクスポート中は進捗が表示されます。ONNX 変換には onnx と onnxsim のインストールが必要で、入っていない場合はポップアップで通知されます。

分類のタスクでは評価レポートを生成しません —— 未検出・誤検出を扱うレポートは分類には当てはまらないためです。OCR のテキスト認識も同様で、結論は CER だけです。

5. テストと評価レポート

5.1 テストパラメータ

モデル管理で行内の「テスト」(または詳細パネルの「このモデルをテスト」)をクリックすると、テストダイアログが開きます。上部にモデル情報が表示されます: タスク種別、重みファイル、学習精度、入力サイズ、規模。その下がパラメータです:

  • データ —— プロジェクトをまたいで、すべてのデータセットを選択できます
  • デバイス —— 既定では最初に使用可能な GPU です
  • 信頼度 —— このスコアを下回る予測はそのまま捨てられます
  • IoU しきい値 —— 予測枠とアノテーション枠の重なりが基準を満たしたときだけ正しく検出したと判定します
  • ラベルファイルを出力 —— チェックすると予測枠を labelme json として書き出し、人手での確認がしやすくなります
  • OCR —— テキスト検出は推論と評価の 2 通りに分かれます。推論は結果をアノテーション json として書き出し、評価は P/R を集計します。テキスト認識はアノテーションファイルを出力せず、切り出し文字の認識率だけを報告します
データセットにアノテーションがある場合は自動的に評価モードになり、検出率 / 未検出 / 誤検出を集計します。テキスト検出で推論モードを選んだ場合は、アノテーションを無視して予測枠をそのまま json に書き出します。

5.2 結果の分析

テストが終わると結果の分析ウィンドウが開きます。2 つの単位で集計し、用語は一貫して分かりやすい「正しく検出 / 未検出 / 誤検出」です:

  • 画像単位(枚数で集計、1 つでも検出すれば検出とみなす)—— テスト枚数、検出した画像と検出率、未検出の画像、誤検出のある画像
  • アノテーション単位(アノテーション枠で集計)—— 正しく検出、未検出、誤検出、正解率
  • クラス別の表 —— 各クラスのアノテーション数、正しく検出、未検出、誤検出、検出率、正解率
  • テキスト認識 —— 枠では集計せず、切り出し文字の総数、CER(文字誤り率)、完全一致した件数を報告します
  • 下部の結論 —— 全体が未検出寄りか誤検出寄りか、そして最も足を引っ張っているクラスを一文で示します

5.3 PDF レポートのエクスポート

右下の「PDF レポートをエクスポート」をクリックすると、バックグラウンドスレッドで生成されます。内容は次のとおりです:

  • 概要ページ —— 指標の集計表 + アノテーション分布図
  • 未検出サンプルのページ / 誤検出サンプルのページ —— 「クラスごとに N 枚抽出」でサムネイルを表示し(枚数は左下で調整)、画像上に未検出と誤検出の位置を赤枠で示し、抽出比率も記載します
  • 提案ページ —— エラー種別ごとに改善の方向性を示します
サンプリングが行われるのはレポートを出すこの段階だけで、明細データはあくまで全量のままなので、後で難例抽出を行ってもデータは失われません。

6. OCR

OCR は他のタスクとは違い、2 つのモデルを組み合わせて処理します —— テキスト検出が文字の枠を見つけ、テキスト認識が枠の中の文字を読み取ります。学習・テスト・エクスポートはいずれも 2 段に分けて行い、モデル管理には 2 件の記録が残ります。

6.1 テキストのアノテーション

アノテーション画面で上部の「テキストアノテーション」スイッチをオンにすると、クラスは自動的に予約ラベル「text」に固定されます(先にラベルを作る必要はありません)。矩形を描くのと同じように文字を囲むと、マウスを離したときに入力欄が開くので内容を入力します。既存のテキストボックスはダブルクリックでいつでも変更できます。

テキストボックスは必ず矩形で描きます。傾いた文字も水平な枠で覆えば問題ありません。学習時にはポリゴンも水平な外接矩形として扱われるため、輪郭をなぞって描いても効果はありません。

テキストボックスを含む labelme json をインポートすると、データセットは自動的にテキスト検出データセットとしてマークされます。以降、この種のデータセットだけが OCR の学習セットのドロップダウンに表示されます。

アノテーションを付け終えてデータセットの表示に戻ると、OCR データセットでは各テキストボックスが1 枚ずつサムネイルとして切り出され、ラベルバーにはクラス名ではなく、枠に入力した文字の内容が表示されます(3 件を超えると +N に折りたたまれます)—— 1 枚ずつめくっていけば、内容が正しく入力されているか確認できます。上部のクラス絞り込みには「text」の 1 項目だけがあります。

6.2 学習

タスク種別で OCR を選びます。

画像サイズは文字認識の学習では使用しません(認識段は 32×768 固定で、入力欄はグレーアウトして 768 を表示します)。

「学習を開始」をクリックすると、自動的に 2 項目に分かれてキューに入ります。まずテキスト検出、次にテキスト認識です。前の項目が終わると、VRAM が学習開始前の水準まで下がるのを待ってから次の項目を開始します。その間、進捗エリアには「VRAM 解放待ち · 次:テキスト認識」と表示され、空白にはなりません。

認識段の語彙表は、アノテーションに出現した文字をそのまま使います。そのため、アノテーションするテキストは現場で実際に遭遇する文字集合を網羅している必要があります —— 現場にあってもアノテーションに出現していない文字は、モデルが認識できません。

6.3 テスト: 検出は 2 通り、認識は 1 通り

  • テキスト検出 · 推論 —— アノテーションと比較せず、予測枠(認識した文字も含む)をそのまま labelme json として書き出します。書き出した json には OCR フラグが付き、ソフトにドラッグして戻すとテキスト検出データセットとして認識されるので、結果の確認や追加のアノテーションに使えます
  • テキスト検出 · 評価 —— データセットにアノテーションがあるときに自動的に入り、正しく検出 / 未検出 / 誤検出とクラス別 P/R を集計します。物体検出のタスクと同じです
  • テキスト認識 —— アノテーション枠から切り出した文字を使ってテストし、切り出し文字の総数、CER(文字誤り率)、完全一致した件数を報告します。アノテーションファイルは出力しません

6.4 エクスポート

2 段それぞれで ONNX を 1 つずつエクスポートします: 项目_字符检测_尺寸_规模.onnx と 项目_字符识别_尺寸_规模.onnx。認識段には vocab.txt の語彙表が別途付きます。

テキスト検出は通常どおり評価レポートを生成します。テキスト認識は結論が CER のみなので、レポートは生成しません。

呼び出しのサンプルはエクスポート先フォルダの examples/python/ocr.py にあります。検出段が出力する logits は sigmoid を通していない点に注意してください。後処理は自分で書く必要がありますが、サンプルにはすでに書いてあります。

7. ログ

ホーム画面の上部にある「ログ」をクリックするとログウィンドウが開き、リアルタイムにスクロール表示されます:

  • ソフトウェアの起動 / 終了
  • プロジェクトとデータセットの作成、名前の変更、削除、インポート / エクスポート
  • ラベルの作成、名前の変更、削除
  • 学習の開始、進行中([train] プレフィックスで子プロセスの出力を転送)、指標の更新、モデルの保存、手動停止
  • テストの開始、進行中([test] プレフィックス)、完了、失敗
