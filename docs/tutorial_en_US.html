Quick Start

From an empty install to your first trained model, the shortest path is these six steps. The details of each step are in the chapters that follow.

  1. Add Project — click "+ Add Project" on the left and type a name.
  2. Add Dataset — right-click the project node → "Add Dataset".
  3. Import Data — select the dataset, click "Import" at the top, and pick the image folder and the label folder separately.
  4. Check the data — click "Dataset Properties" and make sure the classes and counts are right.
  5. Train — click "Train", pick the task type and the dataset, leave the rest at the defaults, and click "Start Training".
  6. Check the results — when training finishes, find the record under "Models" and click "Test" to run it on the val set. If you need to deliver something, export a PDF report.
If you don't have labeled data yet, start with chapter 3, "Labels".

1. Interface and Projects

1.1 Main window layout

The main window has three parts: projects on the left, images in the middle, and the toolbar on top.

  • Project tree on the left — projects and datasets are arranged in a hierarchy. After the dataset comes its labeling progress (such as 126/128); the dot in front of the name shows whether it is loaded into memory, green for loaded, red for not loaded.
  • Image area in the middle — thumbnails browsed page by page. A paging control sits centered at the bottom: two arrows around the page number, with the current page number highlighted. Hover over the page number to see how many images the current filter has in total.
  • Toolbar on top — zoom, the label filter dropdown, and the Edit, Delete, Import, Export, Dataset Properties, Train, Models and Log buttons.

1.2 Projects and datasets

Add Project: click "+ Add Project" on the left, enter a name, and click OK. A project is the container for datasets, and every dataset has to belong to a project.

Right-click a project node:

  • Add Dataset — create a new dataset under the project
  • Export Project — export the datasets and labels of the whole project in a chosen format
  • Rename — rename the project
  • Delete Project — clears the datasets, labels and training records under it as well

Right-clicking a dataset node acts on a single dataset: import / export / move / rename / delete.

Double-click a dataset to load it: the images and labels are rescanned and the caches rebuilt, and after that you can browse it on the right. Double-clicking one that has already been loaded (its row has a status dot) will not scan again.

1.3 Import data

Select the dataset and click "Import" at the top; the import dialog opens:

  • Image path — the folder the images are in
  • Label path — the folder the label files are in
  • Label format — Yolo txt / Labelme json / Import as classification (subfolders)
For a classification dataset, choose "Import as classification (subfolders)": each subfolder name is one class, and no label files are needed.
OCR uses Labelme json; the text box label is always "text", and after import the dataset is automatically marked as a text detection dataset.

1.4 Dataset properties

Select the dataset and click "Dataset Properties" at the top; you can see the image path, the label path, and a label distribution bar chart showing how many annotation boxes each class has. You can tell at a glance which class is short on samples.

1.5 Interface language

The far right of the toolbar is the interface language dropdown, with nine languages to choose from: 中文, English, 繁體中文, 日本語, 한국어, Deutsch, Español, Français, Tiếng Việt.

Once you pick one, the main window switches immediately, and any open Log or Training Queue windows refresh with it. Dialogs that are not open yet come up in the new language the next time you open them. Your choice is remembered, so the next launch is still in that language. Every entry in the dropdown is written in its own language, so no matter what the current interface language is, you can tell which one to pick.

2. Labels

2.1 Open the annotation view

After selecting a dataset, right-click a thumbnail and choose "Labels", or just double-click the thumbnail.

2.2 Draw boxes

The toolbar at the top of the annotation view has three drawing modes:

  • Rectangle — drag the mouse to draw a box
  • Polygon — click the vertices one by one, then double-click or press Enter to finish (for segmentation tasks)
  • Text Annotation — first turn on the "Text Annotation" switch at the top, then drag a box; when you release the mouse an input box pops up for the text, and double-clicking lets you change it (for OCR tasks)

Always draw text boxes with Rectangle. Even tilted text is fine covered by a horizontal box: during training a polygon is treated as its horizontal bounding box, so tracing the outline brings no extra benefit.

The toolbar also has "Delete Image", which deletes the current image.

Pick the class from the label list on the right.

The "Show labels" switch hides all outlines at any time (box lines, labels, vertex handles), which makes it easy to look at the original image. For content that has already been pasted but not yet dropped, only the outline is hidden while the pattern still shows, so turning it off is a good way to preview "what it will look like once pasted".

The "Annotations" panel at the bottom right lists the shape (Rectangle / Polygon), vertex count and area of every annotation object in this image; directly below it, Image Info shows the width × height × channels of the current image (such as 505×505×3) and its index.

Further down is the Clipboard: after you right-click and copy a polygon, a thumbnail of the copied region (120 × 90) is added, up to 9 of them, arranged vertically and scrollable. The newest one is selected by default and carries a blue border; right-click a thumbnail to delete that one, or to clear them all.

2.3 Manage labels

The right side of the annotation view is the label list, with "Add Label" above it:

  • Label name — separate several labels with commas to add more than one at a time
  • Import — copy the labels over from another dataset in one batch
  • Pick Color — choose from the preset swatches, or click "Custom RGB" to pick your own

2.4 Change the class

One at a time: click an annotation box and a class dropdown menu appears; just pick the new class. Labels in the label list on the right can also be renamed, recolored and deleted.

In bulk: right-click a thumbnail → "Batch Change Class", fill in the old class and the new class, and every annotation of that class in the whole dataset is renamed.

2.5 Copy and paste annotation objects

Right-click a polygon annotation and there are two actions:

  • Copy — stores the pixels of this region as a template and, at the same time, creates a thumbnail in the clipboard at the bottom right
  • Fill — changes the pixels inside the region to the RGB color of the three "Fill value" boxes (each channel 0 ~ 255, default 255). Often used to wipe a defect out into the background color

Left-click a thumbnail in the clipboard, then move the mouse onto the canvas and a dashed polygon follows it: the shape is the real outline after rotation, with the angle rolled for this paste already applied. Check the landing spot and the orientation first, press Esc to dismiss the dashed line and go back to the normal mouse mode, then right-click and choose "Paste" to drop it.

Right-click on an empty spot in the image and choose "Paste" to paste the currently selected clipboard item to the mouse position, either on the same image or on a different one. Before pasting, set these items in the toolbar:

  • Angle Range — the angle interval for the random rotation when pasting (default -180 ~ 180). The dashed preview uses the angle rolled from this interval, so what you see is what you get
  • Blend Strength — 0 ~ 1, default 0.70. Pasting automatically applies brightness compensation and edge feathering so the pasted part blends naturally with the background; set it to 0 to paste hard with no blending
  • Fill value — three input boxes for R / G / B (each channel 0 ~ 255, default 255), used together with the right-click "Fill" action to wipe a region to this color
  • Ctrl + Z — undoes the most recent paste or fill: the pixels are restored and any annotations added with it are removed too. You can undo repeatedly

2.6 Adjust the brightness of a polygon region

Select a polygon and turn on Brightness under "Settings" in the toolbar, and you can change how light or dark the pixels inside that polygon box are. Drag the slider or type a value, and the image previews it in real time.

  • Range — 0 ~ 1; the default 0.50 means unchanged. Toward 1 it gets brighter (1.00 is roughly double brightness), toward 0 it gets darker (0 is fully black)
  • Applies only to the selected polygon. For a rectangle, or when nothing is selected, you only get a hint and the pixels are not touched. Click another polygon and the slider goes back to that polygon's own value (0.50 for any that was never adjusted), instead of carrying the previous one's brightness over
  • When it is written to disk — dragging only changes memory and previews in real time. The values go into the image file only when you press A / D to switch images or press Ctrl + S
  • Undo — one adjustment is recorded as a single step, and Ctrl + Z goes back to before it. Dragging back and forth any number of times within the same adjustment still counts as one step

2.7 Filter images by class

In the class dropdown of the top toolbar, once you select a class the image area shows only the images that contain it. Very handy when you want to check or fill in the labels of one class.

3. Train

3.1 Set the training parameters

Click "Train" on the home page or in the Models view and the parameter dialog opens:

  • Task — Detection / Segmentation / Classification / Anomaly Detection / OCR; it switches automatically to follow the dataset format
  • Train Set / Val Set — you can select several, and also combine them across projects
  • Device — lists the available GPUs automatically
  • Epochs / Optimizer / Early Stop — detection and segmentation use adamw and classification uses sgd; Early Stop ends early after N epochs in a row with no improvement, and 0 turns it off
  • Learning rate — decays automatically during training
  • Batch / Image Size / Grad Accum / Threads — Image Size must be a multiple of 32; if you run short of VRAM, lower the batch and raise Grad Accum, which is equivalent to a larger batch
  • Output Path — leave it empty to generate the folder automatically by time, or click "Browse" to specify one

3.2 Training Queue

Once the parameters are set, besides "Start Training" you can click "Add to Queue" to park the task and go on to set up the next one. On the home page, click "Training Queue" to open the queue window:

  • The queue runs in order; Detection / Segmentation / Classification / Anomaly Detection / OCR can be mixed, and it moves on to the next one automatically when a task finishes
  • Move Up / Move Down / Remove — change the running order or delete a task
  • Edit — change the parameters of the selected task
  • Clear Finished — move the records that have already run out of the queue
  • Start Queue — run the queued tasks in order from the beginning
The queue is made for leaving running overnight: set up tasks for several datasets in one go, and the software runs them all and saves a model for each.

3.3 Training progress

After you click "Start Training" and come back to the home page, a progress bar and a control strip appear at the top:

  • Task name + progress — shaped like coco128 training 5/100, with the current epoch's loss shown inside the progress bar
  • Stop Training — stops at any time; the part that has already run is saved
  • Time Left — estimated by extrapolating from the time used so far
  • VRAM — GPU memory usage, refreshed in real time

3.4 Training curves

In Model Manager, select a training record and click "View full metrics" in the details panel on the right; the training curve window opens:

  • The top half is the val loss curve
  • The bottom half holds several curves such as mAP@50-95 / mAP@50 / AR / F1 / precision / recall, and segmentation tasks add one more mask mAP curve
  • The "Label filter" dropdown at the top right switches between all metrics and the curve of one class

4. Model Manager

Click "Models" on the home page to open Model Manager: the training record list is on the left and the details panel on the right.

4.1 List and filters

  • Search box — filters by keyword on project / dataset / label
  • Task / Status dropdowns — for Task you can pick Detection / Segmentation / Classification / Anomaly Detection / Text Detection / Text Recognition; for Status you can pick Training / Finished / Failed / Stopped
  • Best per dataset only — keeps only the highest-accuracy record of each dataset
  • List columns: Task, Dataset / Labels, Accuracy, Trained at, Duration, Image Size, Actions
  • The Accuracy column has a color bar — green ≥ 0.8, yellow 0.5 ~ 0.8, red < 0.5. Failed or stopped records show status text in this column instead, and hovering over it shows the failure reason
  • Three buttons in the row: Test (opens model testing), Export and Delete (which clears the matching training record as well)

4.2 Details panel

Click any row and the right side shows the full parameter set of that record: task · scale, status, accuracy, train / val sets, image size, epochs / early stop, batch size, learning rate, optimizer, device, labels, trained at, duration, model path. Above it there is also a thumbnail of the accuracy curve.

Four buttons at the bottom of the panel:

  • View full metrics — opens the training curve window (see the "Training curves" section)
  • Test this model — opens the test dialog with this model (see the "Test parameters" section)
  • Retrain with this config — brings over all the training parameters of this record and starts a new training run
  • Open model directory — locates the weight file in File Explorer

4.3 Export ONNX

Click "Export" and choose a folder; a "项目_时间戳" folder is generated:

  • Model .onnx — detection and segmentation are exported by RF-DETR, classification and OCR by torch. The name is "项目_任务_图像尺寸_模型规模.onnx"
  • classes.txt — the mapping between class ids and names. For the OCR recognition stage it is vocab.txt, one character per line as the vocabulary
  • Evaluation report PDF — runs an evaluation on the val set automatically, reusing the test report template, named "…_评估报告.pdf"
  • examples/ — C++ / C# / Python sample code that calls the ONNX model for detection, segmentation and classification. OCR currently has a Python version only

The export shows a progress indicator. ONNX conversion needs onnx and onnxsim installed; if they are missing, a popup tells you.

Classification tasks do not produce an evaluation report: that missed/false-positive style of report does not fit classification. The same goes for OCR Text Recognition, whose only conclusion is CER.

5. Test and Evaluation Report

5.1 Test parameters

In Model Manager, click "Test" in the row (or "Test this model" in the details panel) and the test dialog opens. The top shows the model info: task type, weight file, training accuracy, input size and scale. The parameters are below:

  • Data — every dataset from every project can be selected
  • Device — defaults to the first available GPU
  • Confidence — predictions below this score are dropped
  • IoU threshold — a prediction only counts as a correct detection when its overlap with the ground-truth box reaches this value
  • Write label files — check it to write the predicted boxes out as labelme json, which makes manual review easy
  • OCR — Text Detection has two paths, inference and evaluation: inference writes the results out as annotation json, evaluation measures P/R. Text Recognition writes no annotation files and only reports the crop recognition rate
When the dataset has labels it automatically goes into evaluation mode, measuring Recall / Missed / False pos. If Text Detection is set to inference mode, the labels are ignored and the predicted boxes are written straight out as json.

5.2 Result analysis

When the test finishes, the result analysis window opens. It counts on two levels and always uses the plain wording "Correct detections / Missed / False pos.":

  • Image level (counted per image; detecting one item counts as detected) — Images tested, detected images and their recall, undetected images, images with false positives
  • Box level (counted per annotation box) — Correct detections, Missed, False pos., accuracy
  • By class table — for each class: box count, Correct detections, Missed, False pos., recall and accuracy
  • Text Recognition — not counted per box; it reports the total number of crops, the CER (character error rate) and the number of fully correct crops
  • Conclusion at the bottom — one sentence on whether the model leans toward misses or false positives overall, and which class drags it down the most

5.3 Export PDF report

Click "Export PDF Report" at the bottom right; it is generated on a background thread and contains:

  • Overview page — metric summary table + label distribution chart
  • Missed samples page / False-positive samples page — thumbnails shown according to "Per class" (the count is adjusted at the bottom left), with red boxes marking where the misses and false positives are, plus the sampling ratio
  • Suggestions page — an improvement direction for each type of error
Sampling only happens at the report step; the detail data is still the full set, so hard-example mining later will not lose any data.

6. OCR

OCR is different from the other tasks: it is done by chaining two models — Text Detection finds the text boxes, and Text Recognition reads the characters inside them. Training, testing and export are all done in two separate stages, and Model Manager ends up with two records.

6.1 Annotate text

In the annotation view, turn on the "Text Annotation" switch at the top, and the class is automatically fixed to the reserved label "text" (you don't have to create a label first). Box the text the same way you draw a rectangle; when you release the mouse an input box pops up for the content, and double-clicking an existing text box lets you change it at any time.

Always draw text boxes as rectangles: for tilted text a horizontal box is enough to cover it, because during training a polygon is treated as its horizontal bounding box and tracing the outline brings no extra benefit.

When a labelme json with text boxes is imported, the dataset is automatically marked as a text detection dataset. From then on, only datasets of this kind show up in the OCR train set dropdown.

When you have finished labeling and go back to the dataset view, every text box in an OCR dataset is cropped into its own thumbnail, and the label strip shows the text content recorded in the box (more than 3 of them collapse into +N) rather than the class name — flip through them one by one to check that the content was entered correctly. The class filter at the top has only one entry, "text".

6.2 Train

Set the task type to OCR.

Image Size is the input of the detection stage (default 1024, and it must be a multiple of 32); the recognition stage is fixed at 32×128 and is not affected by this setting.

After you click "Start Training" it is automatically split into two queued items: Text Detection first, then Text Recognition. When the first one finishes, the next one only starts after VRAM has fallen back to the level it was at before training began; during that time the progress area shows "Waiting for VRAM release · next:Text Recognition", so there is no idle gap in between.

The vocabulary of the recognition stage is taken straight from the characters that appear in the labels. So the annotated text has to cover the character set you actually meet on site — characters that occur on site but never appear in the labels will not be recognized by the model.

6.3 Testing: two paths for detection, one for recognition

  • Text Detection · inference — does not compare against the labels; it writes the predicted boxes (together with the recognized text) straight out as labelme json. The json carries an OCR flag, so dragging it back into the software makes it a text detection dataset that you can use to check the results or fill in labels
  • Text Detection · evaluation — entered automatically when the dataset has labels; it measures Correct detections / Missed / False pos. and per-class P/R, the same as the detection task
  • Text Recognition — tested on the crops cut out with the annotation boxes; it reports the total number of crops, the CER (character error rate) and the number of fully correct crops, and writes no annotation files

6.4 Export

Each of the two stages exports its own ONNX: 项目_字符检测_尺寸_规模.onnx and 项目_字符识别_尺寸_规模.onnx, with the recognition stage carrying an extra vocab.txt vocabulary.

Text Detection produces an evaluation report as usual; Text Recognition has only CER as its conclusion and produces no report.

The calling example is in examples/python/ocr.py in the export folder. Note that the logits output by the detection stage have not been through sigmoid, so you have to write the post-processing yourself — the example already has it all written.

7. Log

Click "Log" at the top of the home page to open the log window, which scrolls in real time and shows:

  • Software start / exit
  • Creating, renaming, deleting and importing / exporting projects and datasets
  • Creating, renaming and deleting labels
  • Training start, in progress ([train] prefix forwarding the subprocess output), metric updates, model saves and manual stops
  • Test start, in progress ([test] prefix), completion and failure
